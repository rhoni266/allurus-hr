# Allurus POS

Multi-tenant, offline-first, omnichannel POS for the Malaysian market (F&B, retail, time-based services). Full design: `allurus-pos-architecture.md` (schema, sync strategy, API, roadmap). Read it before changing architecture. **Not yet in the repo** — add it before relying on this pointer.

## Stack

* Backend: Laravel 13 (PHP 8.4 locally; keep code 8.3-compatible), PostgreSQL 17 (row-level security), Redis, Horizon, Sanctum, Reverb, Pest
* Back-office: Vue or React SPA
* Terminal: Flutter or React Native, SQLite (SQLCipher), outbox-based sync

## Non-negotiable rules

1. Money is integer sen. Never floats, never `decimal` math in PHP. Quantities are `qty_milli` (qty x 1000) inside the pricing engine.
2. Every tenant table has `tenant_id` and uses the `BelongsToTenant` trait. The scope fails closed (no tenant context = no rows). Postgres RLS is the second wall (`App\Database\Rls::enable()`, with `FORCE` and `WITH CHECK`). Never take the tenant from a client header.
3. IDs are UUIDs generated by the client (terminals create orders offline). Server never re-keys a synced order.
4. Sales are append-only facts. The server never rewrites a completed sale because a price changed. Flag a `sync_conflicts` row instead. Corrections are new rows (void/refund).
5. Stock moves by deltas written to `stock_movements`. `stock_levels` is a projection. Negative stock is allowed and alerted, never blocks a sale.
6. Sync push is idempotent on `(terminal_id, client_seq)`. One DB transaction per mutation. A mutation that fails validation or a business rule is stored as `rejected` and must not block later ones. Transient DB errors (deadlock, serialization, lost connection) and unexpected server exceptions return `retry` and store nothing — never permanently reject a sale for a server-side problem.
7. Pricing lives in one place. `app/Billing/PricingEngine.php` is checked against `spec/pricing/vectors.json`. The terminal (Dart/TS) must reproduce the same vectors. To change pricing behaviour: edit the vectors first, bump `SPEC_VERSION`, then update every implementation.
8. Tax rates are data, not code. SST rules are versioned rows (`tax_rules`), synced to terminals, and the `rule_version` is stored on each order. Confirm current SST rates and scope with the Royal Malaysian Customs Department before go-live.
9. Online-only payment methods (FPX, DuitNow QR, GrabPay, TNG) are disabled offline. Offline = cash only.
10. Payment webhooks: verify signature on the raw body, dedupe by gateway event id, ack fast, process on a queue, and reconcile pending payments with a poller.

### Learned the hard way (each found by the chaos simulator; each has a regression test)

* **The change feed is Postgres triggers, not Eloquent events** (`database/migrations/2026_01_01_000060_create_sync_triggers.php`). `increment()`, query-builder updates and raw SQL skip model hooks, and a missed feed row leaves terminals on a stale price forever. Don't reintroduce PHP-side feed writes. `row_version` is bumped by the trigger, so call `->refresh()` if you need it in memory.
* **Timestamps carry offset and microseconds.** Models use `PreciseTimestamps` (`App\Database\Timestamps::FORMAT`); query-builder bindings must pass `->format(Timestamps::FORMAT)` explicitly. DB sessions are pinned to UTC in `config/database.php`. Device-time columns use `timestampTz(..., 6)` — Laravel's default precision is whole seconds.
* **Terminals are not tenant-scoped and have no RLS**: Sanctum resolves them before a tenant is known.

## Conventions

* Tests first for anything touching money, tax, tenancy or sync. Use Pest.
* Tenant isolation test for every new tenant table: two tenants, assert neither can read or write the other's rows, including via raw queries (RLS).
* Every new sync mutation type gets a simulator scenario as well as Pest tests.
* API: versioned under `/api/v1`, API Resources, cursor pagination, `Idempotency-Key` on non-sync POSTs.
* Queue jobs carry `tenant_id` and call `TenantContext::set()` first.
* Demo data uses `DemoSeeder` only. Demo staff PINs are 1111 / 2222 / 3333.
* Windows PowerShell 5 writes a UTF-8 BOM with `Set-Content -Encoding utf8`, which breaks PHP namespaces. Edit files with editor tools, not PowerShell.
